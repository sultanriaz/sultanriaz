**Repository:** [github.com/sultanriaz/FYP-Medmind](https://github.com/sultanriaz/FYP-Medmind) *(Enterprise Clinical Repo)* &nbsp;|&nbsp; **Stack:** Python (FastAPI), PyTorch (CUDA 12.1), Transformers & PEFT (MedMind LoRA v4), BitsAndBytes (4-bit NF4 Quantization), LangGraph Orchestrator, Next.js 16 (React 19, TypeScript), SQLite Concurrency (WAL + Multi-Process Epoch Lease Fencing), Decimal Physics Evaluator

> **System Purpose:** Enterprise-grade clinical diagnostic intelligence, fine-tuned medical reasoning, and longitudinal health record engine engineered under strict healthcare data-safety standards. Features fine-tuned MedMind LoRA v4 generative model accelerated via 4-bit NF4 quantization on an NVIDIA T1200 Laptop GPU, multi-stage LangGraph clinical reasoning, zero-leak upload boundaries, multi-process distributed epoch lease fencing (`BEGIN IMMEDIATE`, monotonic lease bumping, dead-worker takeover), zero-tolerance Decimal physical quantity evaluation (`rel_tol=0.0, abs_tol=1e-6`), safe clinical abstention on corrupted OCR values, and dynamic SQL query tracing with sub-10ms response times.


- **Trained LoRA v4 & Hardware Acceleration:** Quantized fine-tuned Qwen2.5-1.5B (`MedMind LoRA v4`) with `bitsandbytes` NF4 onto an **NVIDIA T1200 Laptop GPU** (4 GB VRAM, Turing cc 7.5, PyTorch CUDA 12.1). Reduced model memory footprint to **1,169.57 MB VRAM** (28.5% utilization), achieving 100% generative model primacy with 0% silent fallbacks across the 30-case clinical evaluation matrix.
- **LangGraph Clinical Reasoning & Balanced Safety:** Orchestrated multi-stage dynamic retrieval, numerical grounding, reflection, and context-aware emergency safety routing. Enforces strict ADA diagnostic criteria ($\ge 126\text{ mg/dL}$ fasting glucose) and instantaneous emergency escalation for acute events (anaphylaxis, stroke, severe hyperkalemia, severe thrombocytopenia) with zero prompt wrapping and zero fallback degradation.
- **Multi-Process Concurrency Safety:** Connection-level SQLite epoch lease fencing across longitudinal projections and clinical assessment write paths. Validated under genuine subprocess `SIGKILL` termination, mid-rebuild recovery, and monotonic epoch bumping with 0 cross-patient state leakage.
- **Strict Clinical Evaluator v2.0:** Dual-engine evaluation (Validated Decimal Physics & Strict Bipartite Matching) operating at zero tolerance (`rel_tol=0.0, abs_tol=1e-6`). Enforces safe clinical abstention rather than heuristic guessing when OCR boundaries are corrupted.
- **Verified Clinical Corpus & Quality Gates:** **309/309 full backend test suite passing (100%)**, 102/102 clinical corpus cases verified (186/186 measurements matched strictly), 30/30 GPU clinical evaluation matrix passed with zero degradations, 17/17 live negative upload tests with zero DB/filesystem orphan leaks, and dynamic SQL tracing reducing query counts by 99.6% at scale ($N=500$).

### 2. Citerator — Citation-Verified AML/KYC Compliance RAG Platform
**Repository:** [github.com/sultanriaz/citerator](https://github.com/sultanriaz/citerator) &nbsp;|&nbsp; **Stack:** Python (FastAPI), React 19 (TypeScript), Qdrant (Dense + BM25 Hybrid), BGE Embeddings, Cross-Encoder Reranking, Multi-Tenant BOLA/IDOR Security, Langfuse, Ragas, HMAC Audit Ledger

> **System Purpose:** Enterprise-grade Question-Answering and regulatory research engine engineered for AML/KYC compliance analysts. Features cryptographically verifiable source citations, strict default-deny multi-tenant isolation, cross-tenant leak prevention at retrieval/rerank/citation layers, EU AI Act / ISO 42001 compliance controls, and calibrated zero-hallucination refusal guarantees.

```mermaid
flowchart TD
    User["Compliance Analyst / Auditor"] --> ClientUI["React 19 + TypeScript Web Console"]
    
    subgraph "Boundary 1: Server-Side Identity Gate"
        ClientUI --> AuthGate["API Key & Server-Side Tenant Registry"]
        AuthGate -->|"Reject Forged Header / Escalation"| Deny["403 Forbidden"]
        AuthGate -->|"Verified TenantContext"| RouteHandler["FastAPI Application Gateway"]
    end
    
    subgraph "Boundary 2: Scoped Semantic Cache"
        RouteHandler --> CacheLookup{"Tenant-Partitioned Cache (v1:tenant:hash)"}
        CacheLookup -->|"Exact / Semantic Hit"| CachedResponse["Instant Answer (<15ms)"]
    end
    
    subgraph "Boundary 3: Retrieval & Index Filtering"
        CacheLookup -->|"Cache Miss"| HybridEngine["Hybrid Retrieval Coordinator"]
        HybridEngine --> Dense["Dense BGE Embedder"]
        HybridEngine --> Sparse["Sparse BM25 Lexical Embedder"]
        Dense --> Qdrant[("Qdrant Vector DB")]
        Sparse --> Qdrant
        Qdrant -->|"Enforce tenant_id Payload Filter"| RRF["Reciprocal Rank Fusion (RRF)"]

    subgraph "Boundary 4: Pre-Rerank Neutralization"

    end
    
    subgraph "Boundary 5: Confidence Gating & Grounded Generation"
        Reranker --> SigmoidGating["3-Band Sigmoid Confidence Guardrail"]
        SigmoidGating -->|"Score < 0.60 (Insufficient)"| Refuse["Deterministic Rejection & Escalation"]
        SigmoidGating -->|"0.60 <= Score < 0.82 (Low)"| Hedged["Hedged Answer + Mandatory Disclaimer"]
        SigmoidGating -->|"Score >= 0.82 (Confident)"| LLM["Grounding Prompt + Gemini / Claude"]
        LLM --> CitationResolver["Citation Authorization & Excerpt Matcher"]
        CitationResolver --> CacheStore["Store Scoped Cache (v1:tenant:hash)"]
    end
    
    subgraph "Observability & Audit Ledger"
        LLM --> LangfuseTrace["Langfuse Distributed Tracing"]
        RouteHandler --> AuditLedger[("HMAC-SHA256 Tamper-Evident Audit Chain")]

    Hedged --> FinalResponse
```

- **Retrieval Pipeline & Hybrid Indexing:** Dense vector search (BAAI/bge-base-en-v1.5) and sparse lexical BM25 fused via **Reciprocal Rank Fusion (RRF)** in Qdrant, followed by cross-encoder neural reranking.
- **Multi-Tenant Security & BOLA/IDOR Defense (Session 3):** Server-side tenant registry preventing forged `X-Tenant-Id` / `X-User-Role` headers, mandatory Qdrant payload filters during HNSW walk, pre-rerank candidate drop guards (preventing foreign text from entering cross-encoder context), citation resolution tenant authorization, and tenant-partitioned semantic cache namespaces (`v1:<tenant_id>:<hash>`).
- **Confidence Guardrails & Safe Abstention:** 3-band calibrated sigmoid confidence mechanism (`confident` $\ge 0.82$, `low_confidence` $0.60 \le s < 0.82$, `insufficient` $< 0.60$) ensuring out-of-corpus questions are deterministically refused with escalation drafts.
- **Regulatory Governance & Audit Chain:** EU AI Act (Art. 12/14/15) and ISO 42001 automated compliance checks, forward-linked HMAC SHA-256 audit ledger, and GDPR Article 17 right-to-erasure scanning engine.
- **Ragas Benchmark Results & Observability:**
  - **Mean Faithfulness:** `0.97` across test batches.
  - **Refusal Accuracy:** `100%` on adversarial out-of-domain compliance inquiries.
  - **Telemetry:** End-to-end token cost, retrieval latency, and score telemetry traced to **Langfuse**.

### 3. Real-Time Financial AI Intelligence Platform
**Repository:** [github.com/sultanriaz/financial-ai-platform](https://github.com/sultanriaz/financial-ai-platform) &nbsp;|&nbsp; **Stack:** Python (FastAPI), Apache Kafka, PyTorch, HuggingFace FinBERT, spaCy NER, asyncpg, PostgreSQL, WebSockets

> **System Purpose:** Distributed sub-second streaming engine ingesting financial news headlines from major market wires, resolving named entity tickers, computing financial sentiment vectors, and broadcasting actionable insights via persistent WebSockets.

```mermaid
sequenceDiagram
    autonumber
    participant Feeds as Financial Wires (CNBC / Yahoo / MarketWatch)
    participant Scraper as Async Producer (aiohttp)
    participant Kafka as Apache Kafka Broker

    participant DB as PostgreSQL (asyncpg)
    participant Gateway as FastAPI WebSocket Gateway
    participant UI as Financial Dashboard (React/TS)

    Feeds->>Scraper: Polled Headlines & Tickers
    Scraper->>Kafka: Publish Raw Ingestion Event (news-raw-topic)
    Kafka->>Worker: Consume Event Batch
    Worker->>Worker: Extract Companies via spaCy NER -> Map to Tickers
    Worker->>Worker: FinBERT Sentiment Inference (Positive / Neutral / Negative)
    Worker->>DB: Upsert Analyzed Signals & Historical Trends
    Worker->>Kafka: Publish Enriched Sentiment Event (sentiment-enriched-topic)
```

- **Ingestion & Resolution:** Concurrent asynchronous polling of news wires; automated mapping of corporate entity names to standard market tickers using customized **spaCy NER**.
- **Inference Pipeline:** Domain-adapted **ProsusAI/finbert** transformer models running batched GPU/CPU tensor inference to generate directional sentiment polarity and confidence scores.
- **Distribution:** Real-time event broadcasting over asynchronous WebSocket channels with sub-second end-to-end latency and indexed persistence in PostgreSQL via **asyncpg**.
